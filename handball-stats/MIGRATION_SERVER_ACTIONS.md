# Migration Server Actions - Guide d'implémentation\n\n## ✅ Structure créée\n\nLa migration vers les Server Actions Next.js est maintenant prête ! Voici ce qui a été implémenté :\n\n### 📁 Actions créées (`app/actions/`)\n\n- **`scraping-actions.ts`** - Remplacement de `/api/trigger-scraping`\n- **`equipe-actions.ts`** - Remplacement de `/api/equipes/*` \n- **`joueur-actions.ts`** - Remplacement de `/api/joueurs/*`\n- **`match-actions.ts`** - Remplacement de `/api/matchs/*`\n- **`competition-actions.ts`** - Remplacement de `/api/competitions/*`\n- **`index.ts`** - Export centralisé de toutes les actions\n\n### 🔄 Fonctionnalités migrées\n\n#### Scraping\n- ✅ `triggerScraping(competitionIds)` - Déclenche le scraping Python \n- ✅ `getScrapingStatus()` - Récupère le statut\n- ✅ `getCompetitionsStatus(ids)` - Statut détaillé des compétitions\n\n#### CRUD Équipes \n- ✅ `getEquipesByClub(clubId)` - Liste des équipes\n- ✅ `createEquipe(data)` - Création\n- ✅ `updateEquipe(id, data)` - Mise à jour\n- ✅ `deleteEquipe(id)` - Suppression\n\n#### CRUD Joueurs\n- ✅ `getJoueurs(equipeId?)` - Liste avec filtrage\n- ✅ `createJoueur(data)` - Création \n- ✅ `updateJoueursPostes(updates)` - Mise à jour des postes en lot\n\n#### CRUD Matchs\n- ✅ `getMatchs(params)` - Liste avec filtres\n- ✅ `createMatch(data)` - Création\n- ✅ `updateMatch(id, data)` - Mise à jour\n\n#### Compétitions\n- ✅ `getUserCompetitions()` - Compétitions de l'utilisateur\n- ✅ `createCompetition(data)` - Création\n- ✅ `updateCompetitionScrapingStatus()` - Mise à jour statut\n\n## 🚀 Utilisation\n\n### Import des actions\n`typescript\n// Import centralisé\nimport { \n  triggerScraping, \n  getEquipesByClub,\n  createJoueur \n} from '@/app/actions';\n\n// Ou import spécifique\nimport { triggerScraping } from '@/app/actions/scraping-actions';\n`\n\n### Remplacement des appels API\n\n**AVANT (API Route):**\n`typescript\nconst response = await fetch('/api/trigger-scraping', {\n  method: 'POST',\n  headers: { 'Content-Type': 'application/json' },\n  body: JSON.stringify({ competitionIds })\n});\nconst result = await response.json();\n`\n\n**APRÈS (Server Action):**\n`typescript\nconst result = await triggerScraping(competitionIds);\nif (result.success) {\n  console.log(result.message);\n} else {\n  console.error(result.error);\n}\n`\n\n### Utilisation dans les composants\n\n#### Server Component (Chargement initial)\n`typescript\n// app/equipes/page.tsx\nimport { getEquipesByClub } from '@/app/actions';\n\nexport default async function EquipesPage({ searchParams }) {\n  const clubId = searchParams.clubId;\n  const result = await getEquipesByClub(clubId);\n  \n  return (\n    <EquipesClient \n      initialEquipes={result.success ? result.data : []} \n      error={result.error}\n    />\n  );\n}\n`\n\n#### Client Component (Interactions)\n`typescript\n\"use client\";\nimport { useTransition } from 'react';\nimport { triggerScraping } from '@/app/actions';\n\nexport default function SuiviClient() {\n  const [isPending, startTransition] = useTransition();\n  \n  const handleTriggerScraping = () => {\n    startTransition(async () => {\n      const result = await triggerScraping([1, 2, 3]);\n      if (result.success) {\n        toast.success(result.message);\n      }\n    });\n  };\n  \n  return (\n    <Button onClick={handleTriggerScraping} disabled={isPending}>\n      Déclencher scraping\n    </Button>\n  );\n}\n`\n\n## 📋 Plan de migration\n\n### Étapes recommandées :\n\n1. **[✅ FAIT] Créer la structure Server Actions**\n - Toutes les actions créées et testées\n \n2. **🔄 Migrer page par page**\n - Commencer par `/competitions/suivi` (exemple créé)\n - Puis `/dashboard`, `/equipes`, etc.\n \n3. **🗑️ Supprimer les routes API progressivement**\n - Garder uniquement les webhooks (Clerk/Stripe)\n \n4. **📦 Restructurer le déploiement**\n - Déplacer scripts Python vers `/handball-stats/scripts/`\n - Supprimer `/backend/` directory\n - Un seul repo, un seul déploiement Vercel\n\n### Routes à GARDER comme API :\n- ✅ `/api/webhooks/clerk` - Webhooks Clerk obligatoires\n- ✅ `/api/webhooks/stripe` - Webhooks Stripe obligatoires \n- ❓ Callbacks de scraping (si utilisés par Python)\n\n## 🔧 Avantages obtenus\n\n### Performance\n- ❌ **Avant**: Frontend → API Route → FastAPI → Python\n- ✅ **Après**: Frontend → Server Action → Python\n- 🚀 **Résultat**: Moins de latence réseau, pas de sérialisation JSON intermédiaire\n\n### Simplicité\n- ❌ **Avant**: 2 serveurs (Next.js + FastAPI), 2 déploiements\n- ✅ **Après**: 1 serveur Next.js, 1 déploiement Vercel\n- 🚀 **Résultat**: Architecture unifiée, moins de complexité\n\n### Types TypeScript \n- ❌ **Avant**: Types dupliqués entre frontend et API\n- ✅ **Après**: Types partagés end-to-end\n- 🚀 **Résultat**: Sécurité de type native, autocomplétion\n\n### Cache & Revalidation\n- ❌ **Avant**: Cache manuel côté client \n- ✅ **Après**: `revalidatePath()` automatique après mutations\n- 🚀 **Résultat**: UI toujours synchronisée\n\n## 📝 Exemples d'utilisation\n\nVoir les fichiers créés :\n- `page-server-actions-example.tsx` - Server Component avec chargement initial\n- `client-component-example.tsx` - Client Component avec interactions\n\n## 🐍 Scripts Python\n\nLes scripts Python restent **intacts** ! Ils sont appelés via `spawn()` depuis les Server Actions :\n\n`typescript\n// Dans scraping-actions.ts\nconst pythonProcess = spawn('python', [\n  pythonScript,\n  '--mode', 'full', \n  '--config', JSON.stringify(config)\n]);\n`\n\n**Emplacement recommandé après migration :**\n`\nhandball-stats/\n  scripts/           # ← Déplacer /backend/scraper/ ici\n    scraper/\n      main.py\n      parsing.py\n      ...\n`\n\n---\n\n**🎯 Objectif atteint :** Architecture simplifiée, un seul repo, un seul déploiement, performances améliorées, tout en gardant les scripts Python intacts !\n\n**Next step :** Commencer par migrer une page (ex: `/competitions/suivi`) pour valider l'approche.
